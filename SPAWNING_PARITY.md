# Java 26.2 spawning parity work

Base: modern upstream `4e11bb80`, with the independently configurable local
shulker/redstone policy in parent commit `85cced1e`.

This branch corrects biome spawn weights in both generation and natural spawning,
the fixed radius-8 player-chunk union used to scale caps, loaded-entity counting,
density arithmetic overflow, passive cadence based on game time, and sequential
natural-spawn acceptance. Accepted entities enter the world immediately and are
counted once by `after_spawn`; the general entity insertion path still updates
counts for other sources. Chunk block/fluid ticking remains parallel.

The Java fixture was generated by executing the unmodified official 26.2 server
classes (server distribution SHA-1 `823e2250d24b3ddac457a60c92a6a941943fcd6a`).
The generator lives in the hosting repository's `comparison/` directory:
https://github.com/Jplayz2468/mc-server-hoster/tree/main/comparison

Run `cargo test --release -p pumpkin --lib java_oracle_`. It checks 580 global and
local cap cases, 321 potential-energy cases, all tickets in 242 weighted tables,
60 player-chunk footprints, and every one of 32,366 block states against five
representative spawn-floor predicates (161,830 combinations). Biome names,
entity order, weights and state IDs are checked to detect version/data drift.
Floor tests use an empty neighboring block getter; they do not prove every
environment-sensitive block behavior or each mob's full spawn predicate.

**This is not complete spawning parity.** Remaining work includes sharing Java's
RNG stream and draw order, structure spawn-list overrides, species-specific
placement and spawn finalization, special spawning systems, full chunk/ticket
eligibility, and controlled runtime acceptance/rejection traces. The cap itself
is not a hard per-mob ceiling in vanilla: categories are filtered once per tick
and packs may overshoot. Do not change overshoot into a new nonvanilla rule.
